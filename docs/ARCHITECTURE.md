# Архитектура

## Открытое и закрытое

| Открыто (этот репозиторий) | Закрыто |
|---|---|
| SDK: контракт `GameModule`, бинарные хелперы, чексуммы | Сайт: каталог, полноценный рендерер схемы, аккаунты |
| Модули игр | API: каталог, статистика, отчёты об ошибках |
| Devkit — минимальный рендерер для разработки | Инфраструктура, деплой |

Граница между ними — **собранный `dist/`**: `registry.json` + по одному ESM-бандлу на модуль.
Сайт ничего не знает о коде модулей, кроме интерфейса из `packages/sdk/src/types.ts`.

## Жизненный цикл модуля

```
PR → CI (validate, typecheck, tests, build) → ревью мейнтейнера → merge в main
   → CI собирает dist/ → приватный деплой забирает артефакт
   → бандлы на CDN по пути /modules/<id>/<version>.js (immutable), registry.json обновляется
```

Версии бандлов неизменяемы: старый URL продолжает работать, откат — это смена версии в registry.

## Выполнение на сайте

1. Пользователь выбирает игру — сайт показывает `saveLocations` из манифеста.
2. Файлы выбираются через `<input type="file">` / drag-and-drop. Где поддерживается, — File System Access API (папка целиком для игр с несколькими файлами и запись обратно на место).
3. Сайт создаёт выделенный Web Worker, загружает бандл модуля с проверкой `integrity` (sha384 из registry).
4. Worker запущен с CSP `connect-src 'none'`: даже если вредоносный код пройдёт ревью, отправить сейв наружу он не сможет.
5. `parse` → `schema` → форма → `validate` → `serialize` → скачивание. Сайт хранит исходный файл и предлагает его как бэкап.

## Контракт модуля

См. `packages/sdk/src/types.ts`. Ключевые решения:

- **Декларативная схема, а не UI-код.** Модули не зависят от фреймворка сайта, сайт может менять дизайн, не трогая модули, а ревью модуля — это ревью логики работы с байтами.
- **Пути вида `party.0.hp`.** Схема и данные — JSON-подобные, проходят `postMessage`, легко сериализуются (для будущих «пресетов» и шаринга изменений).
- **`serialize(data, original)`.** Патч копии оригинала сохраняет неизученные части формата.
- **Синхронный API.** Если понадобится распаковка/расшифровка — SDK добавит синхронные реализации (zlib, AES), чтобы не тянуть зависимости в каждый модуль.

## Совместимость SDK

`module.json → sdk` — semver-диапазон. Сайт поддерживает несколько мажорных версий контракта одновременно; новые типы полей добавляются в минорных версиях, рендерер сайта игнорирует неизвестные `kind` с предупреждением.
